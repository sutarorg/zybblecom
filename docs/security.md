# Security notes and remaining gates

Implemented: same-origin JSON writes with request/body validation and atomic DB rate buckets; HttpOnly SameSite cookies and Secure on HTTPS; authoritative Supabase user lookup; live admin role lookup; recovery marker signed and scoped to user, session and expiry; request IDs without raw errors; strict provider webhook verification; private response controls; row- and column-scoped database access. No password or session token is stored in application tables. No raw Dodo PII/card payloads are persisted by the app.

`PRICING_COUNTRY_HEADER=1` is for a controlled QA ingress or one that overwrites the header. Do not set it on a public generic server. Supabase Auth limits and CAPTCHA/abuse controls should be verified in staging as directly reachable Auth endpoints do not inherit Next's application-layer rate buckets. Check callback/mail scanner behavior, account revocation and expired sessions with the actual Auth project. Set provider log/URL retention and avoid collecting callback tokens in application telemetry. Add request bucket retention before launch. Server secrets use server-only imports and must be rotated separately by environment.

Not verified: full GoTrue/PostgREST stack, pgTAP in Supabase CLI, Dodo test payment and signed provider callback delivery, long-running settlement reconciliation, recovery email delivery, private R2 CORS/download isolation, ClipSDK source/SSRF controls, admin command authorization and confirmation, production dependency/infra review. Do not infer coverage of these from the local SQL and browser suite.
