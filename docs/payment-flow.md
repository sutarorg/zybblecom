# Test checkout and fulfillment

The shared catalog contains Starter (30; ₹299/$9), Creator (120; ₹999/$19), and Studio (300; ₹2,499/$39). Server geo chooses INR only for India; otherwise USD. No currency toggle. Distinct server-configured product IDs are required. The payment SDK is hard-coded to `test_mode`. Test checkout is separately opt-in.

The checkout handler inserts a pending snapshot before asking Dodo for a session, checks exact tax-inclusive preview total, cart, discounts and currency, and stores the returned session ID before exposing a validated hosted URL. Do not configure coupons, changing taxes or product variations that change the agreed total. Confirm Dodo’s behavior for real billing addresses (including USD outside the US) before opening staging. A failed response is not proof that a provider operation never occurred; a repeated request key does not create a second session. Browser returns only read the owner's purchase and never grant credits.

The webhook uses SDK `webhooks.unwrap` over the raw text and the three Standard Webhooks headers. Only minimal locators and status are retained in the inbox. The handler independently retrieves the payment and matches session, purchase/user metadata, status, product cart, quantity, captured total and currency before invoking the locked grant. Provider retries and simultaneous deliveries cannot duplicate the grant. A granted purchase is not silently debited following a refund/dispute. Such events and mismatches go to review. The synchronous payment webhook handler retains failed/retryable inbox entries; an independent reconciliation sweep, review UI, and alerting are still required. Monitor pending purchases and inbox entries manually during staging. Do not enable live payments.
