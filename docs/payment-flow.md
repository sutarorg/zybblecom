# Dodo checkout and fulfillment

The app uses the pinned **`dodopayments` Node SDK 2.63.1**. `checkoutSessions.preview` and `checkoutSessions.create` use the mode-specific Dodo API (`test.dodopayments.com` or `live.dodopayments.com`); the returned Checkout Session URL must be HTTPS and on `test.checkout.dodopayments.com` or `checkout.dodopayments.com`, respectively, under `/session/`. See Dodo’s [Checkout Sessions guide](https://docs.dodopayments.com/developer-resources/checkout-session), [Create Checkout Session](https://docs.dodopayments.com/api-reference/checkout-sessions/create), and [webhook guide](https://docs.dodopayments.com/developer-resources/webhooks).

## Configure each deployment separately

| Setting                 | Isolated staging / Vercel Preview                                                                                                                                    | Production                                                    |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| `APP_ORIGIN`            | Exact HTTPS staging app origin, with auth and API access working there                                                                                               | `https://zybble.com`                                          |
| Supabase and auth       | A **different** Supabase project from production; stage `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, `SUPABASE_SECRET_KEY`, `AUTH_STATE_SECRET`                       | Production equivalents                                        |
| `DODO_MODE`             | `test_mode`                                                                                                                                                          | `live_mode`                                                   |
| API credential          | `DODO_PAYMENTS_API_KEY`, from Dodo Test Mode                                                                                                                         | `DODO_LIVE_PAYMENTS_API_KEY`, from Dodo Live Mode             |
| Endpoint signing key    | `DODO_WEBHOOK_SECRET`, complete Test Mode signing secret                                                                                                             | `DODO_LIVE_WEBHOOK_SECRET`, complete Live Mode signing secret |
| Product IDs             | `DODO_PRODUCT_STARTER_USD`, `DODO_PRODUCT_CREATOR_USD`, `DODO_PRODUCT_STUDIO_USD`, `DODO_PRODUCT_STARTER_INR`, `DODO_PRODUCT_CREATOR_INR`, `DODO_PRODUCT_STUDIO_INR` | Same suffixes under `DODO_LIVE_PRODUCT_`                      |
| `DODO_CHECKOUT_ENABLED` | `0` until configured, then `1` for that staging scope                                                                                                                | `0` until approved and validated, then `1` for Production     |

Use Vercel environment scopes, not a shared credential across environments. Do not copy test keys/products to Live Mode or enable testing in a preview connected to production Supabase. Vercel Production cannot use test mode, and Preview cannot use live mode even if its origin is misconfigured. Store secrets as sensitive server-only variables and redeploy after changes. Admin Settings reports missing/invalid names and the switch, not credential values or provider health.

Create **six distinct tax-inclusive, fixed-price, one-time Dodo products in each mode**. Starter is 30 credits at $9 / ₹299; Creator is 120 at $19 / ₹999; Studio is 300 at $39 / ₹2,499. Country comes from trusted ingress; only India selects INR. Do not configure coupons, recurring/usage-based pricing, buyer-entered prices or settings that change the locked gross amount/currency. Check relevant customer billing addresses, including USD checkout outside the US, before enabling.

Register the **separate endpoint in each Dodo dashboard mode**: `<APP_ORIGIN>/api/webhooks/dodo`. Give Dodo access through any deployment protection and use that endpoint’s signing secret. Subscribe to `payment.succeeded`, `payment.failed`, `payment.cancelled`, `refund.succeeded`, `refund.failed`, and the supported `dispute.*` events. Turning checkout off stops new sessions, not fulfillment of existing sessions; retain the paired API and webhook keys during a pause.

## If Pay Now is disabled on Credits

**Pay Now** opens Dodo’s hosted checkout for a pack and currency that pass the readiness checks. When checkout is unavailable, the button is disabled with an explanation. On Vercel, open **Admin → Settings → Checkout readiness** on the affected deployment to see the switch and missing or invalid variable names. Check the **Production** or **Preview** scope in Vercel, redeploy after editing settings, and confirm readiness there before testing. Do not set the switch alone: Production also requires `DODO_MODE=live_mode` and the separate live credentials, products, and webhook above.

## Validation and settlement

The authenticated, verified and onboarded creator requests a pack only; the server selects the real product and amount and enforces per-user rate limits. It snapshots the purchase, checks the exact preview totals, cart, currency and tax configuration, and stores the Dodo session ID before exposing the allowed hosted URL. A timeout is not proof that no Dodo session was created; the same request key cannot create a duplicate. A browser return is a status read and never credits a wallet.

The webhook verifies raw bytes using the SDK and Standard Webhooks headers. It independently retrieves the payment in the same mode, compares owner and purchase metadata, session, product, quantity, amount and currency, and invokes the row-locked grant only on verified success. Repeated and concurrent deliveries do not double-grant. Failures/cancellations leave the wallet unchanged; mismatches and reversals require review. Monitor the webhook inbox and pending/review purchases; automatic backfill/reconciliation and alerts are not implemented.

**External acceptance gate:** In Dodo Test Mode, create a session for each pack/currency, confirm a test payment, exercise decline/cancel, replay the signed provider event, and compare the staging ledger. Test Live Mode by previewing and creating a hosted session without entering payment details or paying. Do not infer a live settlement from that no-charge test. No external Dodo calls or payments were made during implementation.
