# Zybble workspace visual refresh

This pass refreshes eight workspace routes and the shared workspace navigation. The approved dashboard remains the design reference: Plus Jakarta Sans, navy text, light borders, white surfaces, and lavender reserved for primary actions and selection. The workspace still uses the same server reads and client action boundaries.

## Design plan and references

- **Give each page one clear focus.** [Awwwards dashboard examples](https://www.awwwards.com/websites/dashboard/) informed the visual reference review. [Linear's UI redesign](https://linear.app/now/how-we-redesigned-the-linear-ui), [Figma UI3](https://www.figma.com/blog/our-approach-to-designing-ui3/), [Notion's sidebar](https://www.notion.com/help/navigate-with-the-sidebar), and [Framer's workspace structure](https://www.framer.com/help/articles/organizations-workspaces-and-folders/) informed the stable, grouped navigation and compact mode.
- **Separate tools from content.** [Vimeo’s library](https://help.vimeo.com/hc/en-us/articles/12426274382609-Vimeo-library-overview) and [Frame.io’s panel overview](https://help.frame.io/en/articles/9101032-panel-overview) informed the dedicated filter rail and media grid. [Stripe’s dashboard](https://docs.stripe.com/dashboard/basics) informed the split between wallet summary, pack comparison, and history.
- **Group forms and keep controls native.** [NN/g’s form guidelines](https://www.nngroup.com/articles/web-form-design/) and [progressive disclosure](https://www.nngroup.com/articles/progressive-disclosure/) informed the three project-creation sections and the support accordion. Use native radios and the native drawer dialog, with [visible focus](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html).
- **Keep tooling and interaction boundaries.** Reviewed [Next.js server/client components](https://nextjs.org/docs/app/getting-started/server-and-client-components), [React inputs](https://react.dev/reference/react-dom/components/input) and [selects](https://react.dev/reference/react-dom/components/select), [Tailwind responsive guidance](https://tailwindcss.com/docs/responsive-design), and [Lucide accessibility](https://lucide.dev/guide/react/advanced/accessibility). The presentation opts in with `.ws-studio` and uses container breakpoints, so a collapsed rail does not force a desktop layout onto a narrow content area.

## Page changes

| Route                   | Visual update and preserved behavior                                                                                                                                                                                                                                                                  |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/projects`             | Separate search, status and order toolbar; up to three project columns with 16:9 source posters. First-run, filtered and unavailable treatments use the existing result branches. Project actions, cursor and query semantics are unchanged.                                                          |
| `/clips`                | Matching library layout with real output aspect ratios and existing clip metadata and actions. Retains search, date, and the project selector only when real projects are available. No new sort or download behavior.                                                                                |
| `/credits`              | Available, Reserved and Used panels; responsive Starter, Creator and Studio comparison. Prices and badges come from the existing catalog and locale resolution. History, pack review links and checkout-state copy remain explicit. A missing balance displays a dash, not zero.                      |
| `/settings`             | Account card and two full-card links. Uses existing identity data; no extra settings destinations.                                                                                                                                                                                                    |
| `/settings/profile`     | Account identity above the original display-name and read-only sign-in email form. No avatar edit; validation, save and status are unchanged.                                                                                                                                                         |
| `/settings/preferences` | Native radio cards for ratio and caption defaults. Keeps the same saved values, optional job email, submit, pending and status behavior.                                                                                                                                                              |
| `/support`              | Native FAQ accordion and contact panel sit side-by-side when space allows. The four answers, help link, subject/message fields and submission gating are unchanged.                                                                                                                                   |
| `/projects/new`         | Source, clip settings and generation summary are visually separated. Wide layouts keep the summary alongside the editor; small layouts stack in reading order. Keeps source verification, upload policy and controls, local draft, generation settings, quote and eligibility logic, and credit link. |

The shared shell uses the existing groups, destinations, nested active states, credit display and identity. The create shortcut is visible in the desktop header as well as mobile. The compact rail retains accessible names and titles. The native drawer keeps its existing backdrop/link/keyboard dismissal and gains more room, touch targets and reduced-motion-aware entry styling. No bottom navigation was introduced.

## Verification

- Before editing and after the redesign, the **unchanged** `scripts/qa/workspace.mjs` passed 13 route states at 8 widths, checked 19 destinations, and passed WCAG-tagged axe scans at 390 and 1440 px, including the drawer. It exercised route redirects, project and clip filters, local draft transfer/retention, invalid input, disabled generation and support, and navigation. No browser errors or mutation requests were reported.
- `scripts/qa/studio.mjs` captured the 64 target-route views at 320, 375, 390, 430, 768, 1024, 1280 and 1440 px with no horizontal overflow. It checked all 18 generation choices, keyboard selection and summary changes, the 500-character limit, four keyboard-operated FAQs, settings cards, credit review/history destinations, collapsed navigation, drawer focus containment and dismissal, and no console errors or mutation requests. Manually reviewed every route at 390, 768 and 1440 px and narrow layouts at 320/430 px.
- `scripts/qa/dashboard.mjs` passed: eight widths, visible upload CTA, native picker/drop/validation, draft transfer/removal and link checks. Before/after crops of the content below the shared header and beside the shared sidebar were pixel-identical at 390, 768 and 1440 px for the dashboard, project detail's unavailable state, clip editor's unavailable state, credits history and the purchase-history redirect (15 comparisons). The approved dashboard source and its CSS block were unchanged in this pass.
- `npm run lint`, `npm run typecheck`, `npm run build`, `npm run test:contracts` (14 passed) and `git diff --check` passed.

**Not verified against live services:** populated project/clip galleries, true first-run/filter-empty service results, authenticated profile and preference saves, support delivery, verified `?source=` reuse, provider upload progress/cancel/retry/resume, paid checkout, clip playback/download or generation completion. The preview has no connected session or adapters for those flows. Their existing branches and contracts were retained; local file selection and disabled controls do not establish that live workflows work.
