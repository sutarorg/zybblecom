# Creator workspace · Session 3

The frontend runs at `/dashboard` in the existing Next.js app. In this session it is an **unconnected preview**, not a signed-in account. No real user, project, file upload, job, balance, purchase, support delivery or output is simulated. File, title and clip choices stay in memory within the workspace and are discarded when the tab reloads or leaves the workspace. Nothing in the preview starts processing or charges credits. No Brand Kit or notification centre is exposed.

[Responsive screenshots](session-3-screenshots.jpg) show the actual disconnected UI. Full route captures are reproducible with `scripts/qa/workspace.mjs` (default output: ignored `test-results/workspace/`).

## Routes

| Route                                                     | Frontend behavior                                                                                                                                                                                                                                                                 |
| --------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/dashboard`                                              | Quick start with drag/browse, recent projects, usage and balance overview, and verified credit activity when available. An unavailable metric renders as a dash, not zero.                                                                                                        |
| `/projects`                                               | Search, status, date sort, cursor navigation, source cards and confirmed deletion when authorized.                                                                                                                                                                                |
| `/projects/new`                                           | File selection and validation, local media metadata, generation options and summary. When integrated, a server upload policy enables transport; a verified upload and sufficient current quote enable generation. `?source=…` continues setup for an authorized uploaded project. |
| `/projects/[projectId]`                                   | Verified source, job settings and stages, reservation state, safe failure/retry, and an aspect-aware, sortable results gallery.                                                                                                                                                   |
| `/projects/[projectId]/clips/[clipId]`                    | Aspect-aware native media controls, source timestamps, metadata editor, optional transcript, and available exports. The native VTT track does not modify burned-in captions. No render overrides.                                                                                 |
| `/clips`                                                  | Cross-project clip library with search, project/date filters, export and original-project links.                                                                                                                                                                                  |
| `/credits`, `/credits/history`                            | Server balance categories, the exact three existing regional packs, and separate purchase and ledger views. `/dashboard/purchases` redirects to `/credits/history?filter=purchases`, including when reached from checkout.                                                        |
| `/settings`, `/settings/profile`, `/settings/preferences` | Account overview, verified name/email/avatar presentation, display-name edit, supported defaults and optional job email preference. No unverified email or avatar changes.                                                                                                        |
| `/support`                                                | Expandable help, existing help centre link and support form enabled only when delivery capability is verified.                                                                                                                                                                    |

The workspace has a collapsible desktop sidebar, modal mobile navigation with keyboard dismissal and focus return, nested breadcrumbs and a compact mobile create/balance header. Data-bearing pages are request-dynamic, noindexed and `private, no-store` with no-referrer policy. The frontend does not enforce authorization; the default adapter returns no private data. Confirmed missing-resource responses get a workspace not-found screen; a disconnected read is **not** proof a record is missing.

## Architecture and integration checkpoints

- **Read and command boundaries.** `src/services/workspace-contracts.ts` defines typed results, paginated queries, capabilities, upload tickets, verified projects, jobs, assets and both ledger record kinds. Install a server adapter in `workspace-server.ts` (server-only, per-request cached profile and balance) and an explicit authenticated same-origin command adapter in `workspace.ts`. The API boundary must schema-validate inputs and project DTOs, rate-limit mutations and return safe codes without provider details. Keep page reads authorized regardless of layouts, prefetching, or intercepted direct URLs. Clear any client draft/private route cache on session/account change.
- **Auth and routing.** Connect Session 2 auth and onboarding with Supabase SSR cookies and a Next proxy for refresh. Check the verified session before _each_ private read and mutation, including downloads, quote/retry, billing and realtime. Enforce owner/RLS access and use uniform not-found responses for out-of-scope IDs. Keep truly private storage/cache keys out of browser payloads; return only signed capability URLs where needed.
- **R2 uploads.** Return an actual input cap and upload mode from `getUploadPolicy`. Issue scoped expiring PUT or multipart tickets on the server; use opaque server-generated keys and treat filename/MIME as hints only. `upload-transfer.ts` sends bytes with XHR, attaches measured progress, signs multipart parts on demand, and sends the final ETags for verification. `use-project-upload.ts` provides cancellation and same-draft retry/resume when the ticket supports it; single PUT retries restart rather than claim pause/resume. Configure CORS preflights, headers and ETag exposure; match retries to verified owner/file/ticket and make finish/abort idempotent. Apply expiry cleanup, inspect actual content, verify final size and obtain trusted duration, dimensions and thumbnail before returning `VerifiedUpload`. Session 3 does not activate these paths.
- **Generation settings.** `generation-schema.ts` is the UI mapping for `clips` (3/5/10/20), `min_seconds`/`max_seconds` (15–30, 20–60, 30–90), `aspect` (9:16/1:1/4:5/16:9), `reframe` (`auto`, `center`, `none`) and `captions` (`bold`, `karaoke`, `minimal`, `false`). Empty AI guidance is omitted; nonempty guidance has a 500-character cap. Independently validate the mapping on the server. Never submit a filename, browser object URL, or user-supplied remote source URL to the provider.
- **Quotes and credits.** Bind short-lived quotes to verified source, settings, user, retry context and processing cost. At start, revalidate quote and balance and atomically reserve credits with idempotency. The browser displays required/available and rechecks expiry, but cannot authorize a charge. Enforce one applicable active job per project/request and reconcile ambiguous network results before re-reserving. Confirmed failures only allow a retry when the backend marks it safe and release is verified. Do not estimate balance from history or infer release from a failed job. Pair Dodo signature verification, idempotent credit grants/refunds, and transaction records with the existing checkout UI. Return URLs are not payment proof.
- **ClipSDK jobs and media.** Submit asynchronously from the server using an expiring reachable source URL and a durable idempotency key. Use verified callbacks or polling with backoff; map provider stages to app states without guessing percent or ETA. Keep `saving` distinct until media is durably persisted; copy MP4/posters/subtitles before ClipSDK's documented seven-day expiry. Serve private playback with signed byte-range URLs and compatible video/VTT CORS, and downloads with attachment disposition and safe filenames. Rerender settings should remain absent unless the adapter actually renders them and can quote their cost. Verify partial results, lower-than-requested counts, missing scores, expired asset links and upload/processing failures.
- **Realtime, settings and support.** Install private Supabase Broadcast scoped to the verified user/project with Realtime authorization. `use-workspace-realtime.ts` coalesces invalidations and cleans up subscriptions; events trigger a verified React Server Component refresh, never an optimistic balance or completion update. Enable preferences, avatar management, support delivery and job emails only for working capabilities. Test account-switch unsubscribe/re-subscribe, revocation, missed events and reconnects. Add validated support delivery and abuse protection before enabling the form.

## QA and performance

- Chromium production build: **13 route URLs × 8 viewport widths** (320, 375, 390, 430, 768, 1024, 1280, 1440); 19 internal destinations verified. Checked page headings, no overflow or broken visible images, console/HTTP errors and selected WCAG A/AA axe rules at 390 and 1440. Reviewed the 390/768/1440 captures after refinements. No browser mutation requests were observed from the preview suite.
- Verified keyboard drawer open/Escape/focus return, collapse/account navigation, project and clip filtering, local browse and drop, invalid file and title, option/summary changes, draft preserved while reviewing credits, unavailable generation and support submission, and checkout-history compatibility. Unit tests cover all 576 settings combinations, invalid choices, local file/title validation, missing/insufficient/expired/eligible credit quotes, and fail-closed service behavior. Auth and workspace unit suites: **7 passed**.
- Regressions: 17 account/system route URLs at eight widths, 27 links; 16 marketing route states at seven widths, 34 links/anchors; no unexpected browser errors. Lint, strict TS, production build and whitespace check passed.
- Lab performance: three cold mobile Chromium runs on each route (390 px, 4× CPU throttle, 150 ms latency, ~1.6 Mbps download). Median LCP: **884 ms** `/dashboard`, **884 ms** `/projects/new`, **868 ms** `/credits`; CLS **0** in those nine runs. Local build and disconnected UI only, not field INP or performance with real media.
- **Unverified until integration:** signed-in/unauthorized account success paths, live uploads and verified progress, populated lists/ledger, real processing/failure/retry, player, real downloads and editing, Realtime, payments and support delivery. No fake provider responses were deployed or used to mark these flows as passing. Safari, Firefox and manual assistive-technology checks are still open.

## Research that informed the UI and contracts

- [Next.js Server and Client Components](https://nextjs.org/docs/app/getting-started/server-and-client-components) and [React external stores](https://react.dev/reference/react/useSyncExternalStore): server-rendered reads and narrow interactive boundaries; refetch after external invalidation.
- [ClipSDK Clips](https://clipsdk.com/docs/clips) and [Jobs](https://clipsdk.com/docs/jobs): supported payload, real stages and expiring outputs; provider limits are not used as an app cap or quote.
- [Cloudflare R2 presigned URLs](https://developers.cloudflare.com/r2/api/s3/presigned-urls/), [R2 object uploads](https://developers.cloudflare.com/r2/objects/upload-objects/) and [MDN XMLHttpRequest upload](https://developer.mozilla.org/en-US/docs/Web/API/XMLHttpRequest/upload): scoped transports and measured bytes, not guessed progress.
- [Supabase SSR](https://supabase.com/docs/guides/auth/server-side/creating-a-client?framework=nextjs) and [Realtime database changes](https://supabase.com/docs/guides/realtime/subscribing-to-database-changes): verified cookies and authorized private events.
- [Carbon file uploader](https://carbondesignsystem.com/building-blocks/core/components/file-uploader/guidelines), [W3C media players](https://www.w3.org/WAI/media/av/player/) and [Adobe's YouTube Creator Studio guide](https://www.adobe.com/express/learn/blog/youtube-creator-studio): file affordances with browse alternative, keyboard/caption constraints, and distinct overview/library/editor workflows. The Zybble UI and artwork are original.
