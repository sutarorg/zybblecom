# Credits and reservations

`available = balance − reserved_balance`. Balance represents owned credits after settled debits. Reservations change only the reserved amount. `reserve_generation_credits` locks the quote/project and wallet, verifies a stored source duration, writes the reservation ledger and durable job task, and returns an existing job only for the same used quote and request key. It is not exposed as a browser operation. Missing or unverified duration cannot authorize generation.

For supported standard media the implementation reserves `ceil(verified_duration_seconds / 60)`, with a 180-minute ceiling. Settlement rounds verified positive billable minutes up once, charges within the reservation, and releases the remainder in the same transaction. Missing or excess usage puts the job into review without releasing the reservation or taking extra credits. Review policy and ClipSDK’s billing for other input types must be agreed and validated before enabling generation. An observed timeout is not proof of cancellation. The release RPC requires a server-recorded failed/cancelled terminal state; the future worker must verify that state with the provider.

Purchase grants lock a frozen purchase, enforce exact verified payment facts and wallet update, and deduplicate by payment ID and ledger reference. Administrator adjustments lock the wallet and verify the administrator's live role, distinct target, reason and idempotency, then append a ledger row and audit row together. A prepare/confirm command endpoint is still required; this RPC is not browser-callable. Credits never renew, reset or expire. No free allowances are minted.
