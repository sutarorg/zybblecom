## Initial findings and risks

- **Launch blocker — media lifecycle:** the customer cannot perform the paid video workflow. Database schema/task fields and a browser upload hook cannot safely stand in for a private R2/ClipSDK pipeline.
- **High — source-bound quote invariant:** `generation_quotes` stores no source asset or duration. `reserve_generation_credits` compares a rounded price to the project's current source without checking the quote was created for that source. Store the immutable source identity/reading and check it under the reservation transaction. Existing unused quotes cannot safely be backfilled from the current source.
- **High — payment recovery:** checkout inserts a purchase before calling the provider but cannot recover a session that succeeded remotely without a locally persisted response. Duplicate keys are rejected without returning previous details. Pending/review cases have no reconciliation worker. The webhook does inline provider lookup; verified event persistence is not operational recovery.
- **High — financial state boundaries:** verified provider facts must reach guarded RPCs only; unverified failure, ambiguous submission, or absent billed usage must never release or consume credits. Confirm app-level grants, refund/dispute ordering and service-role constraints independently in staging before enabling checkout.
- **Medium — profile controls:** the existing settings form attempts `setProfile`, but the client adapter is empty even with a real Auth session. Preferences and support also have no backend, so their UI cannot be counted as operational.
- **Medium — test/deployment gaps:** no CI/container runtime in the initial shell, no local provider credentials, no isolated staging allowlist. Contract labels in old docs describe required work, not implemented features (particularly video, admin and staging). Read-only hosted metadata access is not evidence of a safe test project.
- **Performance risk:** disconnected pages omit database/provider latency; private pages call authoritative Auth and role/profile methods, and gallery/table/archive costs are unmeasured on representative data. Prior reports are Chromium lab LCP/CLS only, not field INP or upload/playback performance.
- **Security/ops gates:** verify managed Supabase roles and grants with actual authenticated clients, review proxy/header trust at ingress, enforce environment separation, monitor departures from financial/job invariants, confirm private media and lease/replay handling, and run backup/restore. Do not infer storage/webhook security for code that does not exist.

## Official references checked before repair

- [Next.js App Router authentication](https://nextjs.org/docs/app/guides/authentication) and [route handlers](https://nextjs.org/docs/app/getting-started/route-handlers): authorization belongs at the data or action boundary; preserve private response caching rules.
- [Supabase SSR](https://supabase.com/docs/guides/auth/server-side/creating-a-client), [RLS](https://supabase.com/docs/guides/database/postgres/row-level-security), [database functions](https://supabase.com/docs/guides/database/functions), [pgTAP](https://supabase.com/docs/reference/cli/supabase-test-db), [Edge background lifecycle](https://supabase.com/docs/guides/functions/background-tasks) and [Cron](https://supabase.com/docs/guides/cron): use a local CLI stack for actual Supabase acceptance; never substitute a linked DB. Persistent database task records are still needed when runtime execution can terminate.
- [ClipSDK clips](https://clipsdk.com/docs/clips), [jobs](https://clipsdk.com/docs/jobs), [webhooks](https://clipsdk.com/docs/webhooks), [errors](https://clipsdk.com/docs/errors), [limits](https://clipsdk.com/docs/limits): documented create idempotency uses identical body/key for 24 hours; terminal job states are not inferred from HTTP status; 3 concurrent account jobs, 7-day file retention, 15-second webhook acknowledgement, five attempts and 300-second timestamp tolerance. The reviewed docs did not establish a dedicated sandbox; do not run paid jobs without owner authorization.
- [R2 presigned URLs](https://developers.cloudflare.com/r2/api/s3/presigned-urls/), [uploads](https://developers.cloudflare.com/r2/objects/upload-objects/), [CORS](https://developers.cloudflare.com/r2/buckets/cors/) and [S3 compatibility](https://developers.cloudflare.com/r2/api/s3/api/): signatures are scoped bearer capabilities; browser CORS and real object verification are separate requirements.
- [Dodo integration guide](https://docs.dodopayments.com/developer-resources/integration-guide) and [webhooks](https://docs.dodopayments.com/developer-resources/webhooks): keep test mode isolated and derive fulfillment from verified server facts, not hosted return parameters.
- [Playwright isolation](https://playwright.dev/docs/browser-contexts), [traces](https://playwright.dev/docs/trace-viewer) and [CI](https://playwright.dev/docs/ci): keep the existing Playwright Core harness and add deterministic inventory, isolation, artifacts and a mandatory gate runner.
- [OWASP API Security](https://owasp.org/API-Security/), [ASVS](https://cheatsheetseries.owasp.org/IndexASVS.html), [upload](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html) and [SSRF prevention](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html): defensive review of identities, ownership, grants, request bounds and provider-facing trust boundaries; no hosted probing.

## Acceptance order

1. Reproduce invariant and UI wiring defects locally, add regression assertions, and apply targeted repairs without rewriting the frontend.
2. Run fresh migrations, existing regressions, production route discovery, accessibility and measured lab performance. Record each blocked category separately.
3. Implement and verify the missing media/admin/operations lifecycle on isolated staging before accepting customer money or videos. Do not declare production ready based on disconnected results.
